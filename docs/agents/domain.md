# Domain documentation

This repository uses a single domain context.

Before exploring or changing domain behavior, read these files when they exist:

- `CONTEXT.md`
- Relevant decisions under `docs/adr/`

Proceed without comment when either location does not exist. Create domain documentation only when terminology or an architectural decision needs to be recorded.

Use terms defined in `CONTEXT.md` consistently in code, tests, issues, and documentation. If required terminology is missing, check whether the project already uses another term before proposing an addition.

Call out any proposed change that conflicts with an existing architectural decision. Name the affected ADR and explain why the decision may need revisiting.
